Run order: `run_rust.py`, `run_spk.py` (needs genesis-vibes crates + specodelic tags under /tmp/proj),
`setup.sh`, `oracle.py`, `eval_py.py` (Python pairs). Paths are hard-coded to the sandbox.

## 1. genesis-vibes (provider) and specodelic (consumer), Rust
- 16 crate versions on crates.io (0.2.0 to 0.12.0), 6 specodelic tags (v0.1.0 to v0.5.0).
- Extractor: tree-sitter over `pub` items (about 345 slots at 0.2.0, 773 at 0.12.0).
- 15 consecutive releases: Cargo's 0.x caret rule calls 5 compatible (the patch bumps); the contract calls 9 accretions and 6 breaks.
  They disagree on 6 transitions: 5 where Cargo is conservative (0.3->0.4, 0.4->0.5, 0.8.3->0.9, 0.10.1->0.11, 0.11.1->0.12) and 1 where a patch release broke callers (0.8.0->0.8.1 added a public struct field).
- Over all 120 version pairs: 14 Cargo-incompatible but accretion; 3 Cargo-compatible but break.
- Compile oracle (local cargo/rustc 1.98.1; `compile_oracle.sh`, verdicts in `compile_oracle_results.txt`, CI reproduction in `.github/workflows/compile-oracle.yml`): each disputed transition probed by pinning a real specodelic tag source to exact `=version` genesis deps and running `cargo check`. 30 verdict rows over the 17 transitions (21 unique compile cells) + 3 supplementary cells; probe = consumer vs provider_to (compiles ⇒ break missed or contract right), control = consumer vs provider_from.
  - 14 Cargo-incompatible-but-accretion: 27 applicable probe cells, all PASS — every beyond-Cargo endpoint that a consumer demand allows compiles, so the accretion claims hold at source level. 3 transitions (0.3.0→0.4.0, 0.3.0→0.5.0, 0.4.0→0.5.0) have no consumer demand (no tag allows 0.4.0/0.5.0) — N/A with recorded reason, not fabricated.
  - 3 Cargo-compatible-but-break (0.8.0→0.8.1/0.8.2/0.8.3, consumer v0.2.0): probe PASS ×3 — v0.2.0 compiles against all three, so no missed break for this consumer (it was already patched, matching its `title:` diff); the contract break stands via the supplementary witness below. Control FAIL ×3: v0.2.0 does not compile against 0.8.0 (E0560 `FeedbackArgs` has no field named `title`) although its declared range `"0.8"` admits 0.8.0 — the caret floor is a live false-pass on the declared range itself.
  - Supplementary (outside the 17, demand-line probes on v0.1.0): PASS vs 0.7.0 (floor), PASS vs 0.8.0 (the §1 "+1 beyond Cargo" demand claim holds at source level), FAIL vs 0.8.1 (E0063 missing field `title`) — the compile-level witness that 0.8.0→0.8.1 breaks a real struct-literal caller while Cargo calls it compatible.
- 0.8.1 is confirmed by genesis' own CHANGELOG (struct-literal callers must add `title: None`) and by specodelic v0.2.0, which added `title:` when it moved from genesis 0.7.0 to 0.8.1; the compile oracle adds the direct E0560/E0063 evidence above.
- 0.11.1->0.12.0 shows no public-surface change; the CHANGELOG declares a behavior break in `lefthook::ensure_wired`, which specodelic v0.5.0 does not use (it uses `ensure_command_wired`).
- Demand per specodelic release: 37, 48, 80, 80, 80 slots. Versions the demand allows beyond Cargo's range: v0.1.0 +1 (0.8.0), v0.2.0 +6, v0.3.0 +3, v0.4.0 and v0.5.0 +1 (0.12.0).

## 2. Flask/Werkzeug and requests/urllib3, Python (execution oracle)
28 consumer-by-provider cells installed side by side and exercised with a smoke test (small, so it understates real breakage).
- Oracle: 24 pass, 4 fail.
- Tool v1 (symbol demand): 23 true pass, 3 false pass, 1 false break, 1 true break (accuracy 0.86).
- Tool v2 (adds call-site arguments): 24 true pass, 3 false pass, 0 false break, 1 true break (accuracy 0.89).
- Declared ranges: 18 true pass, 1 false pass, 6 false break, 3 true break (accuracy 0.75).
- Real catch: Flask 2.2.5 with Werkzeug 3.1.3 fails because `werkzeug.__version__` was removed; the declared range (>=2.2.2, no upper bound) allows it.
- Misses: Flask 3.1.1 with Werkzeug below 3.1 fails because Flask passes `partitioned=` to `Response.set_cookie`. That is a keyword on a method of a returned object; without type inference the demand is invisible. The declared floor (>=3.1.0) catches it.

Caveats: two extractor refinements (`__version__` and module `__getattr__`; call-site arguments) were made after seeing oracle failures, so v1/v2 numbers are optimistic. Small sample (28 cells, 2 pairs).

## 3. specodelic's own CLI and JSON output across releases (real binaries)
Binaries exist for v0.2.0, v0.3.0, v0.4.0 only (checksums verified). v0.1.0, v0.3.1 and v0.5.0 (published 2026-10-03, now "latest") have no binary assets, and the sandbox cannot build them (rustc 1.75 vs 1.88 required).
- CLI contract (`cli_extract.py`, crawls `--help`): 197 slots at v0.2.0, 218 at v0.3.0 and v0.4.0.
  v0.2.0 -> v0.3.0 adds two commands (`archive-companion`, `parse`); v0.3.0 -> v0.4.0 is identical. Both transitions are accretions.
- A first run flagged v0.3.0 as breaking because a new command has a required argument. That was a modelling flaw (a new command's arguments bind nobody), fixed by modelling each command's arguments as a callable signature.
- JSON output shape (lint, graph, doctor over 3 corpora): 438 key-path slots, identical in all three releases.
- Behavior (same commands, same inputs), 3 of 7 command/corpus pairs differ despite identical shapes:
  - `linter.law_cases` became an error in v0.3.0 (+3 issues on the v0.1.0-era corpus).
  - `linter.single_root_reachable` got stricter in v0.4.0 (+8 warnings on the v0.1.0-era corpus, +3 on the v0.4.0 corpus).
  - `doctor` reports a different format revision.
- Exit status: the real corpora did not flip (the old corpus already fails on other rules; the new rule is advisory).
  A constructed spec (a law property without `**identity:**` / `**associativity:**` labels) exits 0 under v0.2.0 and 1 under v0.3.0 and v0.4.0, so a CI gate can flip. That fixture is derived from the rule delta, not found in the wild.
- Release notes for v0.3.0 and v0.4.0 contain only a full-changelog link; no breaking change was declared on the page.
- Reading: tier 1 (shape) passes both transitions; a corpus replay (tier 3) detects both and names the rules.

## 5. Held-out validation of upgrade decisions (wild-1xk)
- `heldout_eval.py` (freeze/verify/split/dev-select/seal/compare/report) + `heldout_corpus.py` + four real checker adapters in `heldout_adapters/`. Corpus derived read-only from the frozen e5 cohort: 4 held-out adjudicable cases (1 definite break, 3 definite ok) + 4 development; the 4 `unresolved` evaluation cases are excluded with recorded reasons (resolution-level refusals have no break/ok outcome). Oracle outcomes come from the cohort's independently graded verdicts (real Cargo replay before any miner tuning), sealed by digest before any held-out comparison; tooling frozen by digest; report carries per-metric denominators with aggregate accuracy deliberately absent. Full artifact map, design rulings, and reproduction: `heldout/README.md`.
- Held-out results (separate denominators, not aggregate accuracy):
  - Declared ranges (`~1.2`, tilde): 0 missed / 2 false-block — the range blocks the compatible 1.8.0 and 1.9.0 updates; the one real breakage (platform-ineligibility, 1.8.0) would also be blocked by range, so 0 missed.
  - CI (consumer test suite under real Cargo): 0 missed / 1 false-block — catches the platform break, but false-blocks intent-change 1.2.4 (behavior change fails the suite though the update is compatible).
  - Ecosystem caret ruling: 1 missed-breakage / 1 false-block — caret declares 1.8.0 compatible and misses the platform break; rejects 2.1.0 (truly compatible).
  - Wild: 0/4 coverage, 4 Unknown — the landed rust-cargo-local-1 profile refuses macro-invoking consumers (`println!` → unsupported-construct + incomplete-demand gaps); honest refusal, reported as a coverage finding, not engineered around. Extractor extension is OpenSpec territory.
- The tradeoff the viability evaluation found is confirmed on held-out data: no single existing check is both safe and permissive; declared ranges false-block compatible updates, the ecosystem caret rule misses real breakages, CI false-blocks behavior changes.
- Caveats: synthetic e5 fixtures (independently graded, small n); wild's 0/4 coverage reflects the prototype's supported Rust subset, not a measured failure rate; human contract-maintenance time unavailable (null, never fabricated). This validates the value proposition, not the future v1 runtime.
- wild-zfw scaled the corpus 4 → 56 held-out cases across 2 ecosystems (cargo + python): the 28-cell flask×werkzeug / requests×urllib3 execution-oracle matrix (§2) imported with its recorded outcomes as oracle, plus 24 fresh cells measured by real installs + smoke runs (23 ok / 1 break), 10 drift-poisoned cells excluded with reasons (python 3.15 stdlib removals; fresh-vs-recorded reproduction agrees 23/28, disclosed per cell in `heldout/python_matrix.json`). Pre-registration enforced: corpus + sealed oracle committed (9d63311) before any wild verdict. The §2 tradeoff reproduces at scale — declared ranges false-block (2/3 cargo, 10/47 python), caret misses the platform break, CI false-blocks intent-change, the python contract tool misses all 4 demand-invisible `partitioned=` breaks (py_wild 0 false-block, 4/5 missed) — and the sealed run recorded a corpus-wide aggregate (99/119 decided runs, denominators in `heldout/README.md`). Lead-side review (wild-p4g): the implementor's aggregate-accuracy report sections violated this ticket's Must gate ("aggregate accuracy still absent from the report") and were removed — the report again renders only the separate metrics; the 99/119 figure survives only in the sealed-run records. Full rulings: `heldout/README.md` (wild-zfw section).

## 6. serde false-break census across the full release history (wild-58c)
- `census.py` replayed serde's full crates.io history: 308 versions (every plain X.Y.Z release, pre-releases excluded, yanked included, crates.io created_at order), 307 consecutive transitions; scratch hygiene held (df-gated batches in /tmp/wild-58c-scratch; extracted trees deleted per version). Pre-registration (crate, version list, methodology) was committed (0a5cc07) before any transition was graded; per-release and per-transition tables with denominators: `census_results.txt`.
- Slot counting used BOTH extractors per version. PRIMARY surface/verdict engine: the tree-sitter prototype (`wild_proto.extract_rust`) — per-release surface ranges 0→598 slots (min 0 is serde 0.0.0's empty src/lib.rs; ≥300 satisfied from 0.2.0 onward), 120,630 slots summed over all 308 releases. SECONDARY: the current wild extract binary — it refused complete inventory on 307/308 releases (denominator: versions with a manifest; the one accept is 0-slot 0.0.0): serde's `macro_rules!`/glob-reexport surface defeats the strict rust-cargo-local-1 profile on every real release, so "current extractors at scale" currently means the prototype path for this crate.
- Opaque share: 19,972 opaque / 19,972 inventoried slots (numerator/denominator, wild binary over all releases) = 100.0% — every slot serde's profile does inventory is fingerprint-only (serde's public surface is types and traits, not scalar functions), i.e. verdict Unknown for the v1 checker everywhere it applies.
- False breaks (contract=break AND Cargo caret compatible AND no documented/digestible break evidence in the TO-version's release notes): 21 / 24 candidate transitions (numerator/denominator) = 87.5%, or 21 / 307 over all graded transitions = 6.8%. Detail rows are dominated by textual-signature over-sensitivity (2018-edition path spellings like `::actually_private::T` → `crate::…`, `Sized`-bound additions counted as output-type breaks, private-module reorganizations) — the prototype contract still over-claims breaks that neither Cargo nor release notes corroborate; 35/307 graded transitions are contract breaks at all, and 11/11 Cargo-incompatible transitions were also contract breaks (0 Cargo-conservative disputes).
- Caveats: verdicts come from the prototype shape checker (the wild binary cannot grade serde — it refuses); release notes are the only documented-evidence source consulted (no compile oracle ran at this scale), so "false break" means uncorroborated, not proven-safe; yanked and the back-published 0.9.15-after-1.0.0 transitions are kept and graded as released.

## 7. Dynamic-language arm: metaprogramming-heavy extraction coverage (wild-pe1)
- `dynamic_arm.py` ran the prototype Python surface path (`wild_proto.extract_py`, the census.py invocation) over a PRE-REGISTERED 14-fixture metaprogramming matrix (fixture list, diagnostic-usefulness rubric 0=none/1=mechanism/2=mechanism+locus, and the decision rule were frozen in commit b9b9d1f before any extraction; per-fixture rates table with explicit numerators/denominators: `dynamic_arm_results.txt`).
- Python arm: aggregate Unknown rate 20/32 = 62% (denominator: known-surface members documented in each fixture header). Usefulness of the Unknowns: 6/10 fixtures' worst gap is grade 0 — the extractor silently omits runtime-created names (globals() injection, exec-built APIs, computed `__getattr__`, metaclass-injected methods) or inventories pre-patch shapes as fact (monkey-patch / class-replacement fixtures, `monkeypatch-blind`); grade 2 fires only where `__getattr__` declares its served names explicitly (1/10 fixtures, `dyn` shape = mechanism + locus). Control: a dispatching decorator with static defs extracts fully (0/2 unknown), so decorators per se are not the wall — runtime name creation is.
- The prototype Python path has no refusal machinery: it never reports Unknown, it silently omits (extract-only arm; `incomplete-demand` N/A, pre-registered).
- JS arm: no JS extractor exists in the prototype — recorded as the finding (4/4 fixtures unsupported-extractor, N/A rates), not engineered around.
- Verdict (pre-registered rule): IMPRACTICAL for the dynamic arm as-is — 62% aggregate Unknown with 6/10 fixtures carrying undiagnosed grade-0 gaps and JS uncoverable; a scope-narrowing signal: dynamic-surface coverage needs a diagnosing refusal layer before Unknown-with-diagnostics can be claimed useful here.
