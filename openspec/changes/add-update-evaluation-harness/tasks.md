# Implementation sequence

Progress is tracked in Beads wild-aoq; comparative research is wild-1xk. These are delivery criteria, not a parallel status list. Runtime work awaits proposal approval.

1. Define the evaluation schema and immutable protocol/task/attempt/oracle/task-result records. Implement deterministic record validation and summary with the numeric example in design.md, zero denominators, missing costs, policy exclusions, duplicate ids, unresolved oracles, and artifact mismatches.
2. Prepare the narrow independently specified E1/E4 development fixtures and native Cargo update pair first (wild-aoq.5), independently of the metric engine. Expand the full E5 cohort in wild-aoq.2; freeze its sealed split before comparative trials and never use it for miner tuning. Preserve genuine range exclusion checks and scoped oracle outcomes with separate policy eligibility. Initial extraction and host-adapter work need only the narrow fixture predecessor.
3. Implement common isolated execution, all-arm authority/protection, fixed budgets/order, private oracle access, and complete attempt accounting. Demonstrate that an unauthorized acceptance-rule edit cannot bypass any arm's actual baseline.
4. After wild-mh5 and wild-nic supply working commands, connect all A-D adapters and run the smallest real Cargo update pair. An ordinary existing-tool arm must have the same range-change and migration authority. Validate actual artifact/closure commitments before grading.
5. Expand to the four range/compatibility cells and the transitive, singleton, runtime, dynamic, wrong-target, migration, intent-change, and failure fixtures. Preserve unknown/error outcomes and publish reproducible synthetic results with scope limits.
6. Register the new capability's dual-format spec and actual scenario contracts, including updating the nine-capability assumption in tests/test_gate_wiring.py when the new capability is archived; run strict validation, correspondence checks, harness tests, and repository CI. Before wild-1xk starts E3, freeze the protocol, margins, held-out split, and budgets and resolve product-alignment review wild-6ig. E3/E7 success is not a completion condition for the harness itself.

Release integration and authorized post-delivery archive belong to wild-aoq.4. Independent review belongs to wild-aoq.6 after delivery; it returns defects to the integration owner and does not create its own implementation. The parent remains open until both succeed. Dynamic fixture preparation in wild-aoq.2 does not complete the actual-treatment scenario owned by wild-aoq.3.
