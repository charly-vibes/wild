## Result record

Each run records protocol/manifest digest, phase, case and variant id, H/S factors, source and implementation identities, exact assembly and mapping, accepted oracle/profile, observation adapter, fixtures, scheduler/domain bounds, method, structural assurance, law status, policy decision, execution outcome, diagnostic, trace, counterexample and the protocol's cost ledger. Record independent oracle identity and expected fields before execution. These are research records, not v1 extensions.

Separate schema/input errors, incompatibility, insufficient evidence and harness failure. A missing implementation is NOT EXECUTED, never a passing unknown-handling control. DEFERRED cases are excluded from the phase denominator by the protocol's frozen applicability table; required missing runs remain visible. Freeze exact variant inputs, expected outcomes and oracle before comparison; changes require a new manifest and invalidate affected comparisons.

## Decision rules

Use the protocol's FAILED/INCOMPLETE/PHASE_READY rules. Every required variant must match its frozen expected fields; supported positive controls must accept. C02, C03.unused, C05.shared, C07.unchanged and the valid C09 controls apply from P1; C12 positives apply from P2; C15's discharged-premise positive applies in P3. C07's changed-artifact variant refuses stale evidence, then evaluates fresh evidence as a distinct run. Any unsafe acceptance blocks readiness. Publish per-variant results; do not pool toy, schema and runtime evidence or count timing repeats as independent observations.

Compare only phase-ready arms with the same frozen workload and cost conditions. Report setup, authoring, update, review/repair, execution and exit costs separately, including failed attempts and unknown sunk costs. Use protocol-defined amortization and cold/reused conditions. Readiness does not select a winner: practical margins and acceptable regressions must be frozen before confirmation; otherwise selection is INCONCLUSIVE.
